# Shell repair audit

Audit run: 2026-07-29, live Hyprland session on `eDP-1` (1920x1080, scale 1.0), Quickshell 0.3.0.

The reference video named in the task was not present at `/mnt/data/shareExample.mp4` in this workspace, so the behavioural comparison below uses the requested interaction contract and the live shell reproduction.

| Issue | Current trigger | Current command or signal | Expected behaviour | Observed behaviour | Root cause | File responsible | Repair approach |
|---|---|---|---|---|---|---|---|
| Top bar is a full-width visual strip with weak hierarchy | Persistent bar | `Bar.qml` `PanelWindow` | Thin, quiet shell chrome; controls remain distinct, readable and owned by their panels | Live layer is `1920x40`; screenshot shows wallpaper strip with low-contrast small controls and no clear ownership | Bar geometry and surface styling are split across ad-hoc pills; no central trigger metadata or active state | `shell/noxflow/Bar.qml`, `shell/noxflow/theme/Tokens.qml` | Use a shared trigger registry, stronger type/contrast hierarchy, and explicit active/hover/pressed ownership states |
| Bar controls do not reliably open their panels | Clock, notification, network/Bluetooth/volume/battery controls | `shellRoot.coordinator.toggle(...)` | Click the control and open its matching contextual panel from that control | Calendar click produced no panel layer; other controls opened a right-side layer only in some cases | Bar reaches an implicit root id and controller selects by active screen; calendar content is loaded through an undefined/unstable component map and has no explicit trigger record | `shell/noxflow/Bar.qml`, `shell/noxflow/core/PanelController.qml`, `shell/noxflow/core/MorphSurface.qml` | Make root services explicit aliases, make panel lookup null-safe, and route every item through a registry entry |
| No actual origin-aware morph | Any bar panel trigger | `MorphRegistry.registerChip(id, rect)` plus `MorphSurface.openPanel()` | Surface expands from the exact trigger rectangle into its target rectangle, preserving origin and easing | Layers appear at final geometry; the panel's own scale animation is independent of the trigger, so the chip-to-panel relationship is not visible | Registry stores only a bare rect, open geometry is overwritten immediately by `moveToTarget()`, and panel content scales separately | `shell/noxflow/MorphRegistry.qml`, `shell/noxflow/core/MorphSurface.qml`, panel QML files | Store the complete trigger record and animate one host window from source bounds to target bounds; keep content opacity separate |
| Central dashboard is oversized and visually dominant | `Super+D` / `noxctl panel toggle dashboard` | `hypr/conf/40-binds-launch.lua`, `cli/noxctl/src/main.rs` | Compact contextual workspace surface with clear hierarchy and reliable dismissal | Live screenshot shows a centered ~800x620 card over a full-screen scrim, with dense clipped content and weak contextual relation | Dashboard is implemented as an independent full-screen modal and uses fixed 85%/800x620 sizing | `shell/noxflow/surfaces/dashboard/Dashboard.qml` | Reduce to a bounded contextual card, improve scroll/layout bounds, and give it explicit root/focus/dismiss handling |
| `Super+D` dismissal path is broken | Escape after dashboard/launcher | `noxctl` `handleEscape` IPC | Escape closes the topmost active surface | IPC call logged `TypeError: Cannot call method 'handleEscape' of undefined` | `surfaceCoordinator` is an internal id, not an exposed root property in the IPC scope | `shell/noxflow/shell.qml` | Expose the coordinator through an explicit alias and make IPC handlers return safely |
| `Super+Space` launcher is poor | `Super+Space` | `noxctl panel toggle launcher` -> `toggleLauncher()` | Fast, keyboard-first launcher with immediate focus, useful results, and reliable Escape | Full-screen overlay contains a relatively large modal card; launcher cache/scanning is delayed and the shell logs repeated provider timeouts | The launcher is a heavyweight full-screen surface, starts a desktop-file scan after opening, and competes with the separate rofi implementation | `shell/noxflow/surfaces/launcher/Launcher.qml`, `hypr/conf/40-binds-launch.lua`, `hypr/scripts/launcher.sh` | Keep one canonical launcher path, open a compact focused surface immediately, and remove blocking/deferred first-use work from the initial interaction |
| Panel IPC vocabulary is inconsistent | `shellctl` and `noxctl` panel commands | `hypr/scripts/shellctl`, `cli/noxctl/src/main.rs` | One command vocabulary should address the same surface as bar and keybind triggers | `shellctl` uses compatibility names (`toggleQuickSettingsPanel`, `toggleMediaPanelFromIpc`) while direct `noxctl` uses different names; `shellctl close` only closes major panels | Aliases were added in multiple layers without one registry/controller contract | `hypr/scripts/shellctl`, `shell/noxflow/shell.qml`, `cli/noxctl/src/main.rs` | Normalize aliases to the same panel registry/controller and close all shell surface classes through one dismissal path |
| Runtime QML errors | Shell startup and panel interaction | Quickshell journal | No repeated warnings when idle or opening a panel | Journal shows `MorphSurface.qml[60/71] TypeError: Value is undefined...` and `Tokens.qml[169] TypeError: Cannot read property 'r' of undefined` | Component map is indexed before it is ready; `withAlpha()` assumes every caller passes a valid color | `shell/noxflow/core/MorphSurface.qml`, `shell/noxflow/theme/Tokens.qml` | Guard component maps and color inputs, then verify clean startup and clean trigger logs |
| Monitor/scaling geometry is implicit | Multi-monitor or scaled display | `Bar.qml` `mapToItem(null,...)`, `MorphSurface.qml` screen dimensions | Trigger coordinates and target dimensions use the same monitor-local coordinate space and scale | Current session is one 1920x1080 monitor; code mixes global-looking chip rects with screen-local right margins and fixed panel widths | Trigger records do not include monitor/scale and target fitting is incomplete | `shell/noxflow/Bar.qml`, `shell/noxflow/MorphRegistry.qml`, `shell/noxflow/core/MorphSurface.qml`, `shell/noxflow/config/Metrics.qml` | Register monitor name and complete geometry, normalize to the selected screen, fit width/height to that screen, and use scaled metrics |
| Workspace number click does not switch workspace | Click a workspace number in the bar | `Bar.qml` `focusWS()` | Dispatch the selected workspace immediately | The click sent a provider action through `noxd`; live logs showed provider action timeouts and Hyprland stayed on the current workspace | Workspace focus was coupled to the asynchronous noxd provider path; this Lua-configured Hyprland also rejects legacy `hyprctl dispatch workspace <name>` syntax | `shell/noxflow/Bar.qml` | Dispatch `hyprctl dispatch 'hl.dsp.focus({ workspace = "<name>" })'` directly, validate the target, and use the same direct path for wheel cycling |
| Workspace indicator stays on the old number after keyboard switching | `Super+1`, `Super+2`, or another compositor workspace binding | Hyprland `workspace` event → `HyprlandModel.activeWorkspace` | Active pill changes for keyboard, mouse, and external compositor changes | The model received the event-backed active workspace, but the bar read the older `monitors[].activeWorkspace` snapshot | `monitorActiveWS()` preferred a slower monitor snapshot over the event-backed active workspace | `shell/noxflow/Bar.qml` | Prefer `hyprland.activeWorkspace` for the focused monitor, retaining the monitor snapshot for non-focused monitors |
| Control Centre tabs overlap and Wi-Fi rows do nothing | Right status cluster → Control Centre → Network/Wi-Fi row | `PanelController.toggle()` → Control Centre tab/NetworkManager action | The selected section is readable; a saved Wi-Fi row reconnects; the panel remains compact during the morph | Seven long tab labels were forced to equal widths, and scanned AP records have SSID/strength but no saved-profile UUID, so the old action sent an empty UUID | `ControlCentre.qml` used an equal-width tab row and always called `network_connect_saved` with `modelData.uuid` | `ControlCentre.qml`, `PanelController.qml`, `MorphSurface.qml` | Use a clipped horizontal tab scroller, pass the requested section through the shared host, and activate saved profiles with `nmcli connection up id <SSID>` |
| Control Centre appears dim or oversized during open | Any status icon → Control Centre | Shared MorphSurface geometry animation plus Control Centre lifecycle | A compact, opaque surface expands from the trigger without content flashing or being clipped | The target height was the full remaining monitor height and the inner panel independently scaled from 0.85 with opacity 0→1, producing a weak intermediate surface | `MorphSurface.qml`, `SurfaceLifecycle.qml`, `ControlCentre.qml` | Bound quick settings to a 720px cap, use non-bouncy cubic easing, and let the shared host own the morph while the panel stays stable and opaque |

## Reproduction evidence

- `hyprctl layers -j` while idle showed only the Quickshell bar at `0,0 1920x40`.
- Opening quick settings produced a Quickshell layer at approximately `1490,88 423x901`.
- Opening notifications produced `1528,88 380x1016`; opening media produced `1528,88 380x421`.
- Opening the calendar through the same `shellctl open calendar` path produced no panel layer.
- Opening the launcher produced a full-screen `0,40 1920x1040` layer in addition to the bar.
- `noxctl panel toggle dashboard` produced the same full-screen layer; the captured dashboard card was approximately 800x620 and centered.
- Calling the advertised Escape IPC handler produced the journal warning that `surfaceCoordinator` was undefined.
- The active service is `noxflow-shell.service`, PID 685613; no Waybar process or Wayle layer was active during the test.
