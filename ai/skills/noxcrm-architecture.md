# Skill: noxcrm-architecture

## When to use
NoxCRM-specific code paths, conventions, and boundaries.

## Inputs required
Feature area, touched apps/packages, and user flow.

## Process
1. Map frontend, mobile, and API touchpoints.
2. Reuse established TypeScript, React Native, and backend patterns.
3. Highlight shared-module risk and ownership boundaries.

## Output format
Architecture notes, entry files, and implementation guardrails.

## Safety / guardrails
Do not invent NoxCRM modules that are not in the repo.
